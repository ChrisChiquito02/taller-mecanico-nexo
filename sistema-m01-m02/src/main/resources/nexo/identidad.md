identity/security/DatabaseJwtAuthentication.java; identity/service/UserAdministrationService.java; db/migration/V2__sessions_and_rbac.sql
profile:read
El catálogo inicial V2 tiene USER (profile:read) y ADMIN (profile:read, users:read, users:write). profile:read permite ver el perfil propio y cambiar contraseña. users:read permite listar usuarios; users:write asignar roles y desactivar cuentas. Estos son valores iniciales: una simulación real lee el catálogo activo de la base autorizada. Cada petición JWT valida emisor, expiración, estado de cuenta y session_version en base; las autoridades se calculan desde roles activos actuales. Asignar roles incrementa session_version y consume tokens, incluso asignar los mismos roles. No existe endpoint IAM para editar permisos de un rol. El refresh rota y usa cookie HttpOnly, Path=/api/auth y SameSite=Strict por defecto. Logout cierra todas las sesiones. Recuperación es por SMTP. USER no administra otras cuentas. NEXO no asigna ni revoca roles: solo simula.
